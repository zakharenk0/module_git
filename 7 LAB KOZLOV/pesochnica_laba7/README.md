# Песочница паттернов GoF — лабораторная работа, вариант 7

**Предметная область:** сортировочная станция.

| Паттерн | Что варьируется в варианте 7 | Файл «после» |
|---|---|---|
| Factory Method | фабрика создаёт **тип отцепа** (по назначению, транзитный, ремонтный, местный) | `FactoryAfter.java` |
| Strategy | **очерёдность расформирования** состава (по назначению, по массе, по типу вагона, по приоритету) | `DismantlingAfter.java` (дополнительно к обязательному образцу `TariffAfter.java`) |
| Observer | наблюдатели получают событие **«состав расформирован»** | `ObserverAfter.java` |

## Как запускать

Требуется Java 11 или выше (проверено на JDK 17). Каждый файл самопроверяется и печатает `[OK]` / `[FAIL]`; при провале любой проверки выбрасывается `AssertionError`.

В Colab (из блокнота):

```text
!java TariffBefore.java
!java TariffAfter.java
!java FactoryAfter.java
!java ObserverAfter.java
!java DismantlingBefore.java
!java DismantlingAfter.java
```

Локально в Windows (для корректной кириллицы в выводе):

```text
java -Dfile.encoding=UTF-8 FactoryAfter.java
```

Диаграммы строятся командой `plantuml -tpng <файл>.puml` (в Colab — после `apt-get install plantuml`).

## Самопроверка

В блокноте заполнены ФИО (`Захаренко М.А.`), группа (`ГИ-41`), `Номер_варианта = 7` и флаг `ТАБЛИЦА_И_ВЫВОДЫ_ЗАПОЛНЕНЫ = True`. При повторном запуске ячейки §8 в Colab она сформирует такой же отчёт; готовый отчёт самопроверки лежит в `outputs/selfcheck.md`.

## Что важно в реализации

- В `main` файла `FactoryAfter.java` нет ни одного `if`/`switch` по типу отцепа: работа идёт только через `OtsepCreator` и `Otsep`. Четвёртый тип добавлен новыми классами `LocalOtsep` и `LocalOtsepCreator`.
- `Station` не знает конкретных наблюдателей: подписка, отписка и уведомление идут через `DismantlingListener`. Четвёртый наблюдатель `AsuIntegration` добавлен без правки `Station`.
- Порядок доставки события «состав расформирован»: при первом событии `табло → журнал → рассылка`, после отписки табло и подключения АСУ при втором событии `журнал → рассылка → АСУ`.
- Старые реализации сохранены в файлах «после» как эталоны для характеризующих тестов: они доказывают, что рефакторинг не изменил уже работавшее поведение.
